GUIDE · RENDERING

Pixel-perfect cameras and camera UI

Enable Pixel Perfect on an orthographic camera. Reference Width and Reference Height define the pixel window; Pixels Per Unit relates source texels to world units. The defaults are 320 × 180 and 32 pixels per unit.

Match the scene density

Auto Pixels Per Unit derives density from a visible tile-map layer: tile width in pixels divided by cell width in world units. The authored Pixels Per Unit is the fallback when no eligible layer resolves. Turn automatic density off for an explicitly authored grid. A scene with mixed tile densities cannot make every density pixel-perfect with one camera.

Automatic density is enabled by default. To retain an existing camera's explicitly authored density in a scene with tile maps, disable Auto Pixels Per Unit.

Pixel Snap stabilizes the camera translation against the grid. Enable Expand to reveal extra world for a mismatched viewport aspect; disable it to keep the reference window and letterbox unused space.

Editor views and the Player

Editor Game View and Scene View enlarge the low-resolution image by an integer scale. The Scene View's 2D mode follows the scene density and uses integer zoom steps. Reverse Scroll Wheel Dolly reverses the 2D wheel direction too. New textures dropped into a 2D view become sprites sized for that scene density, with one unit per pixel when no tile-map density resolves. Existing sprites retain their authored size.

The standalone Player applies camera framing and pixel snap at window resolution. Its runtime host does not currently allocate the low-resolution targets used by the editor's integer upscale crossing.

Display-resolution effects

The shipped Forward Plus pipeline includes PixelPerfectUpscale after temporal antialiasing. Custom graphs can place that node before effects that should run at display resolution. Its output uses the output extent and passes through when pixel-perfect rendering is inactive. Without the node, the editor Game View enlarges the finished image and HUD with a nearest upscale.

Camera effects on game UI

Include UI In Post Processing is enabled on cameras by default. With it enabled, game UI is composed into the camera image before fullscreen effects. Disable it to keep a crisp HUD outside camera effects. This controls game UI, independently of editor chrome. Custom pipelines need the supported post-process composition point for the camera UI hook.

CRT pixel size

The CRT effect rounds its emulated-resolution divisor to a whole number of screen pixels per emulated pixel: 5.6 becomes 6. Zero selects 6. The slider advances in whole pixels; choose a whole divisor to control the rendered size.
