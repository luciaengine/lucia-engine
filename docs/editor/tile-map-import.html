GUIDE · TILE MAPS

Import Tiled and LDtk maps

Import orthogonal Tiled .tmx maps or LDtk .ldtk projects into native .tileset and .tilemap assets.

  1. Put the source map under the project's Assets folder. Keep atlas images and external .tsx tilesets or .ldtkl levels under the source map's directory.
  2. In the Assets browser, right-click the source file and choose Import as Tilemap.
  3. Review importer errors and warnings in the log. The imported native assets are written beside the source and registered with the asset registry; map layers reference the registered tileset GUIDs.
  4. Continue authoring with the Tile Palette and terrain and rule tools.
Re-import asks before replacing any existing native outputs. Cancel leaves the existing .tileset and .tilemap files untouched. Confirming Replace discards painting, layers and IntGrid values added after the original import; preserve a separate copy when retaining those edits.

The import finishes with a notice listing the outcome and warnings. A write or registration error can leave some outputs on disk; the notice reports this so you can inspect them before retrying.

Scripted import

The tilemap_import debug request takes a UTF-8 source path and optional boolean overwrite. Omitted or false refuses an import that would replace existing native outputs, before writing any of those outputs. A refusal lists conflicting UTF-8 paths in details.existing. Retry with overwrite: true only when replacing those files is intended. Atlas registration may create metadata while parsing.

Source files and paths

Root maps and external Tiled tilesets must be regular files. Missing files, directories, FIFOs, and device files are refused before reading. An unreadable or non-regular external LDtk level is skipped with a warning.

Atlas images and external references must stay within the source directory tree, including through symlinks. An LDtk atlas outside that tree fails the import. Move the image under the source directory and update its relative path before importing again. Paths and diagnostic names preserve Unicode.

Budgets and compressed layers

The importer shares its budgets across the complete source project: at most 64 MiB of source files and 16 million decoded cells, with additional per-layer, nesting, and output-chunk limits. Split large source projects when a limit is reported.

Tiled tile layers support CSV, base64, and base64 compressed with zlib or gzip. Zlib is a required engine dependency. Compressed output must match the declared layer or chunk size exactly; corrupt, truncated, or oversized streams are refused. Zstd and XML-element tile data are unsupported: export CSV or base64 instead.

Supported map content

Tiled imports finite and infinite orthogonal maps, inline or external atlas tilesets, layer groups, tile flips and rotations, animations, custom tile properties, and rectangular or polygonal collision shapes. A layer using several tilesets becomes one native layer per tileset, with a warning. Object and image layers, image-collection tilesets, and non-orthogonal layouts do not become native tile layers.

LDtk imports tile, auto-layer and IntGrid data, external levels, tile flips, custom tile data and enum tags. Auto-layer output becomes painted cells; source rules and inter-level world layout are not imported. Each level gets its own map coordinates. When several tiles occupy one cell, the topmost survives. Entity layers are skipped; missing external levels generate warnings.

Parsing or budget failure produces no imported native output. A later write or asset-registration failure can leave earlier outputs on disk, as described above. Resolve the named cause before retrying; split oversized maps or move external files and atlases beneath the source folder.
