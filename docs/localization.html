Engine localization

The Localization module provides shared C++ catalogs, ICU MessageFormat, and live Label bindings. It does not require managed scripts or process-global game state. ICU implements language rules; the engine owns catalog loading, stable StringId keys, fallback and UI lifetime.

Native API: localization catalog loading, language selection and label binding are C++ APIs; C# bindings are not supplied.

Create and translate a catalog in the editor

The editor exposes Window → Localization, provided by the localization editor package. It also appears in the toolbar Panels menu and initially docks beside the Scene View. Open a .localization catalog or create entries with a key and English source. Add BCP-47 target languages, filter keys, edit translations, context and translator notes, and save the catalog. The entry fields are a draft: Apply commits it and Discard restores the applied entry. Switching entries or languages, starting a new key, saving, and PO exchange first commit valid edits; invalid ICU patterns or mismatched translation arguments remain visible for correction and block those actions. Filtering never commits a draft; the edited key stays listed even when the filter would hide it. Saving refuses to overwrite a catalog modified externally since opening. Native saves publish a complete temporary sibling through the shared filesystem service.

The language list shows names and tags, for example Dutch (nl), with missing counts. A hollow ring marks a missing translation; a filled dot marks an unapplied draft. Invalid draft fields scroll into view and take focus. Selecting a different message fills preview Arguments with the source argument names and sample values of 2; context and translator notes appear beneath the source, with a translation-length comparison.

The missing-translation report lists absent or empty values and plural messages missing categories required by the target locale, before fallback. Explicit numeric cases do not substitute for a locale’s named plural categories. The preview formats the draft entry using JSON arguments (strings or numbers); missing entries show the runtime fallback. Pseudolocalization is preview-only: after ICU formatting it accents vowels, adds approximately one-third padding and boundary markers. It does not change catalog patterns, game locale preferences or shipping translations.

Translator context and notes are stored in the optional $metadata catalog object, indexed by textual translation key, with string context and notes members. Runtime catalog loading validates this metadata and ignores it for message resolution.

CheckMessage(pattern, locale) validates with the same ICU parser as runtime formatting and supplies an author-facing problem, fix, and one-based Unicode code-point position when available. MessageArgumentNames(pattern) returns sorted unique argument names; MissingPluralCategories(pattern, locale) reports uncovered cardinal or ordinal categories. LanguageDisplayName(tag) supplies the English name shown beside a language tag. The panel warns when its preview font and configured fallbacks cannot render the preview text.

PO export uses stable keys as msgctxt, English ICU patterns as msgid, translated ICU patterns as msgstr, and extracted comments for context and notes. Import checks the language header when present, rejects changed English source and duplicate or unknown keys, and validates the entire result before adoption. Empty and fuzzy entries preserve existing translations. Multiline quoted strings and UTF-8 are supported. Keep ICU plural/select patterns in a single entry: gettext msgid_plural/msgstr[n] arrays are rejected explicitly. Translator metadata stays with the source catalog; imported PO comments do not overwrite it. This module does not supply translations or certify font coverage, bidirectional layout, Arabic shaping, or CJK rendering. The Text module remains responsible for shaping and fonts. Windows, Linux, WebAssembly and packaged game acceptance need platform testing before claiming support there.

Catalog files

A UTF-8 JSON file contains language tables with stable message keys. English (en) is the source and final fallback. A missing translation falls back per key, while an empty translation intentionally displays nothing.

{
  "en": {"menu.play": "Play", "coins": "{count, plural, one {# coin} other {# coins}}"},
  "nl": {"menu.play": "Spelen", "coins": "{count, plural, one {# munt} other {# munten}}"}
}

All messages compile at load time. Malformed ICU patterns, invalid UTF-8, duplicate JSON members, duplicate normalized locales, and mismatched translation placeholders fail the entire replacement and retain the working catalog. Errors identify the message where available. Translations must preserve all argument names, including nested branches. Untranslated keys may be omitted.

Messages and fallback

Use complete ICU messages so translators can reorder words and choose plural or select branches. Named arguments accept UTF-8 strings, signed 64-bit integers and doubles. Supply every argument declared in the message, including conditional branches. Missing arguments or formatting failures return the authored fallback, with an optional diagnostic. Literal braces must use ICU quoting. See the ICU message guide.

Locale selection accepts BCP-47 tags and legacy underscore separators. ICU normalizes tags and derives parent locales: for example nl-NL → nl → en. Unicode locale extensions do not create separate translation tables. Invalid tags do not change state. Formatting uses the language of the selected translation, including when it falls back to English.

Load a catalog asset

Catalog documents use the .localization extension and register as Localization assets. Load one through the asset pipeline, then call LocalizationAsset::CreateCatalog(error) on the loaded asset. This creates independent locale state for a UI context. Failed asset loads preserve the last valid document. Existing contexts remain snapshots until the host replaces their catalog; unloading the source asset does not invalidate them.

Alternative: load from C++

std::ifstream stream(packagedCatalogPath); // Path inside the staged application/project
std::string error;
auto catalog = std::make_shared<GameEngine::Localization::LocalizationCatalog>();
if (!catalog->Load(stream, error)) { /* display error; keep the previous catalog */ }

The JSON format above can be written by a tool or loaded from any UTF-8 input stream. Load validates and replaces the catalog atomically. Keep ownership of a catalog to change its locale or reload it later.

Assign the catalog once to the UI manager

// ui is the application's initialized GameEngine::UIManager.
ui.SetLocalizationCatalog(catalog);
if (!catalog->SetLocale("nl-NL", error)) { /* display error */ }

The manager owns the catalog and its single change subscription. Locale changes, successful catalog reloads and catalog replacement refresh all its bound labels and invalidate their text layout. Labels retrieve the catalog from their owner; callers do not pass catalogs to individual controls. Moving a label between managers uses the new owner's catalog. Clearing the manager's catalog restores literal fallback text. Perform catalog and UI updates on the owning UI thread.

Bind strings in UXML

<Label id="play" localization-key="menu.play" text="Play" />
<Label id="coins" localization-key="coins" text="Coins" />

localization-key identifies the catalog entry. text is a literal fallback, used when no catalog is assigned, no matching entry exists after language fallback, or formatting fails. It is not a translation entry and is not interpreted as an ICU pattern. An intentionally empty translation displays nothing. Removing the key during UXML reload removes the binding. UXML and C++ use the same binding state.

Alternative: bind strings from C++

auto play = std::make_unique<GameEngine::Label>();
play->BindLocalization(GameEngine::HashStringId("menu.play"), "Play");
ui.GetRootElement()->AddChild(std::move(play)); // Inherits this manager's catalog.

auto coins = std::make_unique<GameEngine::Label>();
GameEngine::Label* coinLabel = coins.get(); // Valid while the UI tree owns the label.
coinLabel->BindLocalization(GameEngine::HashStringId("coins"), "Coins",
                            {{"count", int64_t{1}}});
ui.GetRootElement()->AddChild(std::move(coins));

Bind before or after attaching the label. A detached label displays its literal fallback. Call ClearLocalization() to remove the binding and keep the currently displayed text. SetText sets literal text and removes the binding, even when the literal matches the current translation. Subsequent locale or catalog changes leave that literal unchanged. BindLocalization requires a nonzero key; key 0 logs a warning and displays the supplied fallback unbound.

Update dynamic message arguments

Arguments supply values for named ICU placeholders. For the pattern {count, plural, one {# coin} other {# coins}}, pass a numeric count; ICU selects the plural branch and formats the number. String arguments can fill names or select branches. Supply all declared arguments, including those in conditional branches.

// In the application's coin-count change handler:
coinLabel->SetLocalizationArguments({{"count", int64_t{22}}});

This replaces the label's stored argument values and immediately refreshes its text. Call it when the application value changes, not every frame. The binding does not watch arbitrary game variables. Changing the language or reloading the catalog reuses these values automatically. UXML labels use this same method for dynamic values after finding the label by id.

Fonts and Unicode text

Translation and font selection are separate. Choose a font-family in CSS and supply the desired font through the shared font resolver. A custom resolver can supply ordered packaged fallback paths in UIManager::FontResolveResult::FallbackFonts. The host chooses their order and any locale-specific primary font. There is no directory scanning or filename-based language policy. Standalone text users can configure FontAtlas::SetFallbackFonts before loading the primary face. Packaged fallback paths preserve Unicode directory names. If no configured face covers a character, the missing glyph is not rendered and the text system logs one warning per font-atlas instance and primary font family/script pair; add an ordered fallback face covering that script.

TextShaper owns Unicode segmentation, HarfBuzz shaping and cluster-level fallback selection. FontAtlas stores the resulting glyph resources and caches measurements. Its language setter forwards a shaping hint and invalidates measurement caches only when the hint changes; it does not choose fonts or rebuild glyph textures. HarfBuzz needs a language hint because the same Unicode text and font can use different language-specific OpenType substitutions. und is the BCP-47 tag for “undetermined”, used when no language preference is known.

Text uses ICU bidirectional and grapheme runs with HarfBuzz shaping. The Text module shapes with an explicitly supplied primary font and ordered fallback files. Whole clusters select a covering face, preserving combining sequences. Selection rectangles follow visual clusters, including disjoint ranges in mixed-direction text. Text-field arrow navigation and multiline vertical hit testing use visual caret stops rather than assuming increasing UTF-8 byte positions. Stops remain on shaped-cluster boundaries. Backspace and Delete use ICU extended grapheme boundaries, preserving combining marks, joined emoji and flag sequences as editing units. Unicode word selection and word-wise movement use ICU dictionary boundaries, including Thai and CJK, while retaining the editor’s dot and colon behavior for identifiers. Word-wise arrows choose the next word boundary in the requested visual direction for Unicode text. Normal wrapping uses ICU line-break opportunities over the complete paragraph, including dictionary segmentation for Thai and boundaries for CJK text; style boundaries do not introduce word breaks. Break-all and keep-all retain their explicit overrides. Shaped clusters are never split by wrapping. Styled spans are ordered using the complete line’s bidi runs and retain that line as HarfBuzz joining context. Mixed font sizes share a baseline.

Locale resolution preserves exact region and variant matches, then uses ICU likely-subtag script matching before a generic language fallback. For example, zh-TW can resolve a zh-Hant table. This does not select an unrelated default region.

Text warmup

After styles resolve, call UIManager::PrepareTextSubtree on the owning UI thread before revealing a screen. It resolves styles beneath hidden containers without revealing them, visits hidden text too, shapes fallback glyphs and registers curve, band and color atlas resources. Pending means preferred font requests or initial style/render setup are still in progress; Ready means the text resources have been prepared; Failed reports a missing font or resource allocation failure. Rewarm after changing text, locale, font style or display scale. The game loading adapter uses this result with its level-resource readiness gate.

Language preference

SetSystemLocale initializes the catalog from ICU's platform locale. RestoreLocale reads a bounded language tag from a host-owned stream, preserving the current locale on invalid input. WriteLocale saves the canonical selected tag. The host chooses its writable application data path; catalogs never resolve runtime paths into the source repository. UIWindowDemo uses its application data directory and saves language changes from F6.

Build and packaged example

CMake finds ICU uc, i18n and data components from the vcpkg manifest. ICU headers remain private to the implementation. ICU data must accompany shared-library builds; standard runtime dependency staging handles linked libraries. Retain ThirdParty/ICU/LICENSE.txt in distributions; CMake install and the example copy the complete notices.

UIWindowDemo loads Localization/menu.localization beside the executable, independent of the working directory. Its title and count use one catalog. Press F6 to cycle English, Dutch, Polish, Japanese, Korean, Simplified Chinese, Traditional Chinese, Arabic, Hebrew, Hindi and Thai; F7 adds a coin to exercise plural changes. The catalog, layout, default font, compiled shaders and notices are staged by CMake. Supply project fonts for scripts absent from the default font before using those locales. The registered LocalizationTests also load the staged catalog. This example is a small integration fixture, not a complete translated game.

Fonts for project UI

Import a font covering the scripts your game displays and retain its license. Set the UI elements’ CSS font-family to the imported family, for example through a class on the root while that language is active. Project family resolution does not automatically supply fallback faces. Missing glyphs render nothing and produce a diagnostic naming the font and script. Font coverage and translation are separate concerns.

Font packaging

The engine does not ship an all-language font pack. Projects must package and license fonts covering the scripts they support. The Text tests stage a small set of Noto fixtures only for regression testing; these do not enter Editor or Player distributions. Test fixture provenance and OFL notices live with the test fonts. Test coverage is not a claim of complete language coverage.

Browser file exchange

The editor imports catalogs and PO files through the shared browser picker. Save catalog and Export PO request browser downloads rather than overwriting the original host file. Complete the download in the browser. Imported temporary files are released after reading.
